US-009 Close the signS3Path absolute-path passthrough in preview — DONE 2026-05-29
app/store/preview/[templateSlug]/page.tsx. Removed the AC-4 hole: the old signS3Path treated any value starting with development/|tenants/|templates/ as "absolute" and signed it VERBATIM, so a layout.json value `tenants/<other>/secret.png` would be signed cross-tenant. New behaviour: (1) reject `..`/backslash up front; (2) resolve relative values under the current s3Prefix; (3) re-validate the resolved key — tenant preview uses isKeyInTenantScope(key, tenantId, {folderPrefix}) (the no-throw boolean from US-002, exercised by US-003's 15-test bypass suite), marketplace preview requires the key to stay within the previewed `templates/{slug}` prefix; (4) out-of-scope → return null (skip, never sign) so the rest of the page still renders. tenantId is derived from the already-tenant-scoped s3Prefix via tenantIdFromPrefix() (regex `(?:^|/)tenants/([^/]+)/`) — no hardcoded template values, no new data source (per AC notes). Threaded tenantId into ALL signS3Path calls incl. the two array-item calls. signLayoutAssets still uses Promise.allSettled and now only overwrites the target when the result is a non-null in-scope URL, so a dropped asset never breaks the others (AC-4a). signature of signLayoutAssets/signDefaultAsset unchanged (tenantId derived internally from the s3Prefix they already receive), so no outer call sites changed. tsc --noEmit exit 0; pnpm test 15/15 green (no regression).
