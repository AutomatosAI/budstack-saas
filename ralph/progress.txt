  which is TCP-unreachable from this machine. Rather than defer every DB-backed
  surface, stood up a throwaway local Postgres 17 (homebrew, port 55432, /tmp data

  `prisma migrate diff --from-empty --to-schema-datamodel` piped to psql.
  Chose migrate-diff over `db push`/`migrate dev` deliberately: psql can only reach
  the local socket, so there is no path by which the live URL could be touched.
- FOUND: `prisma migrate deploy` CANNOT build this schema from empty. The first
  migration (20260108_add_user_profile_fields) ALTERs `users`, which no earlier
  migration creates — it fails P3018 / 42P01. The 40 migration dirs are an
  incremental history over a pre-existing database, not a from-scratch baseline.
  Relevant to every later Prisma story: a new migration is appended to that history
  and applied by entrypoint.sh against an already-populated DB; it can never be
  validated by replaying the directory from zero.
- FOUND: the checked-out node_modules Prisma client was STALE — it predated
  platform_leads, so `PlatformLeadStatus` was missing and BOTH `tsc --noEmit` and
  `next build` failed on app/super-admin/leads/page.tsx before I touched anything.
  `pnpm prisma generate` fixes it. Pre-existing local-env state, not a code defect,
  but any fresh clone hits it.
- Seeded a tenant whose designSystem is deliberately magenta/violet (primary
  #B5179E) precisely so BudStacks green (#52D97A) leaking through would be obvious,

DEV MODE CANNOT VERIFY THIS — the finding that shaped the run
- Under `pnpm dev` the tenant post rendered with DEFAULT navy links and markers and
  every `--tenant-color-*` var unset. Cause is NOT the typography sweep: the app's
  CSP (lib/security/csp.ts) omits 'unsafe-eval' for the "base"/"store" variants,
  Next.js dev compiles with eval, so hydration dies on
  `EvalError: Evaluating a string as JavaScript violates ... 'unsafe-eval'`.
  TenantThemeProvider applies its vars in useEffect, which therefore never runs.
  => Any storefront theming check MUST be done against `pnpm build && pnpm start`.
  A dev-only look would have reported a false failure here.
