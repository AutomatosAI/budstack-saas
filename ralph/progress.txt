THE MASTER-TENANT FALLBACK, AND THE BINDING THAT MAKES IT WORK
A store renders its OWN conditions plus a configured master tenant's shared ones
(app/store/[slug]/conditions/page.tsx:24-36; the detail API has the same
fallback). generateMetadata mirrors that resolution or it would title a fully
rendered page "Condition Not Found".

The load-bearing detail: applyTenantScope spreads the CONTEXT tenantId OVER the
where clause — `{ ...where, tenantId }` (lib/db.ts:115-118). A master-tenant
read issued under the visiting tenant's context is therefore silently rewritten
to the visiting tenant and can NEVER match. So loadCondition binds each read to
the tenant it is actually reading: runWithTenantContextAsync(tenantId, …) for
the store's own row, then runWithTenantContextAsync(masterTenantId, …) for the
shared one. The explicit tenantId in the where is what makes each query correct;
the binding is what makes it legal (conditions is tenant-scoped, lib/db.ts:61,
and generateMetadata resolves OUTSIDE the layout's context scope — unbound it
warns security.tenant_context_missing and would throw under
TENANT_CONTEXT_STRICT, inside metadata, where a throw is a blank page).
findFirst with flat fields throughout, never findUnique on the tenantId_slug
compound (the $extends rewrite rejects a compound key).

parseEntityId, NOT parseUuid
conditions declares `id String @id` with no database default, so an id is
whatever the writer supplied — crypto.randomUUID() today
(scripts/seed-conditions.ts:497), but nothing enforces it, and parseUuid would
400 a perfectly valid row. parseEntityId is [A-Za-z0-9_-]{1,64}: wide enough for
a uuid, cuid or nanoid; narrow enough that nothing reaching a where clause can
carry a wildcard, quote, path separator or whitespace. Added beside the other
two path-param gates rather than inlined, and named as the looser option so it
does not become the default.

DECISIONS
- TEXT COLUMN, NOT A PRISMA ENUM. An enum would make "unknown column value"
  impossible at the DB and turn a bad value into a write error — which
  contradicts the fail-closed AC and would drift from the datamodel. Parsing is
  the boundary instead: exact-match, no trim, no case-fold.
- FAIL-CLOSED LANDS ON 'basic', NEVER 'trial'. trial grants everything, so a
  parse failure resolving there is a free upgrade for anyone who can corrupt a
  row. Every unhappy path — unknown value, missing row, query throws, call site
  omits plan — resolves to the paid floor. Pinned by 10 parametrised cases plus
  three getTenantPlan cases.
- DEFAULT 'trial' on the column is fail-OPEN, and only here. Every existing
  tenant is inside the launch window the seam already grants all features to, so
  backfilling as 'trial' preserves exactly today's behaviour. The DENIAL path is
  the fail-closed one. Reasoned in the migration header so it reads as a
  decision, not an oversight.
- ANALYTICS KEYS UNTOUCHED ON EVERY PLAN. AC-2 is explicit that the analytics
  basic/pro split is the analytics module's pending decision. BASIC_FEATURES
  carries all four analytics.* keys, and an it.each over PLANS asserts it, so a
  drive-by edit has to argue with a red test.
- requireFeature WRAPS THE HANDLER, NOT THE ROUTE. That is what lets one
  function serve both requirePermission (2-arg) and requirePermissionParams
  (3-arg) — generic over the trailing args, params forwarded untouched. The
  sanctioned order is requirePermission(key, requireFeature(feature, handler)):
  auth and permission deny FIRST, so an unauthorised caller never costs a plan
  query and never learns the tenant's plan. Asserted both ways (findFirst not
  called on 401 and on permission-403).
- 403 SHAPES ARE DISTINGUISHABLE. Permission denial keeps the bare {error}; plan
  denial adds code:'upgrade_required' + feature + plan. Without that the client

[2026-08-14] US-018 PASS — OG image studio: branded generation
================================================================================

WHAT WAS ACTUALLY MISSING. Every builder Workstream A built ends its image
cascade with "or nothing" — an owner who never pasted an ogImage got no
og:image, which is the grey row Slack/WhatsApp/LinkedIn render for a link they
could not preview. app/api/public/og/route.tsx now mints a 1200x630 card from
the tenant's own logo, brand colour, business name and page title, and
lib/seo/og-image.ts wires it in as the LAST entry of that cascade.

LAST, not first — deliberate. An authored seo.ogImage wins, then the entity's
own picture (post cover, Dr Green strain photo, condition image), and only then
the generated card. A photograph the author chose previews better than anything
we can draw. Where the card actually earns its keep is the pages that never had
an image to lose: /products, /how-it-works, the four legal documents, The Wire
index, and most seeded conditions.

WHAT GOES IN THE URL, AND WHY SO LITTLE. Two params: `kind` (a closed enum) and
`title` (capped at 90 chars, truncated by the builder AND re-checked by a Zod
schema in the route). Everything that makes the card the TENANT's — logo,
colour, name, printed host — is resolved from the request HOST, never the query,
so a crafted URL cannot dress one store's card in another store's branding. The
headline is the single caller-controlled pixel. That is a deliberate, stated
acceptance rather than an oversight: signing the params would need a new secret
and a new deploy variable, and a fail-closed signature check means no OG images
at all on a misconfigured deploy. FLAGGED for review below.

FOUR DEFECTS FOUND BY RENDERING RATHER THAN REASONING. The PNG path cannot be
unit-tested (WASM rasterise), so it was driven directly through next/og in a
scratch harness and the output images were looked at:

  1. CACHE HEADER SILENTLY DOUBLED. ImageResponse builds its headers as
     `{ "content-type": …, "cache-control": …, ...options.headers }` — a plain
     object spread, so "Cache-Control" and "cache-control" are DIFFERENT keys
     and both reach the Headers constructor, which comma-joins them. The
     response carried `public, immutable, no-transform, max-age=31536000,
     public, max-age=3600` and a browser takes the FIRST max-age: a year of
     immutable caching on an image that must change when an owner rebrands.
     Fixed by using the lowercase key so the spread actually overrides. Now
     emits exactly `public, max-age=3600, s-maxage=86400,
     stale-while-revalidate=604800`.

  2. LONG UNBROKEN TITLES RAN OFF THE CANVAS. Satori will not split a run with
     no break opportunity, so a 90-char product name with no spaces (a SKU, a
     compound word) was clipped at the right edge. `wordBreak: "break-word"` on
     the headline; re-rendered the cap-length worst case both ways to confirm.

  3. WEBP AND AVIF LOGOS THROW, they do not degrade. Measured: the same 64x64
     square as png/jpeg/gif each rendered an identical 845-byte card; webp and
     avif threw "a is not iterable" — and they throw from INSIDE the
     ReadableStream, which is consumed after the handler has returned, so the
     route's try/catch cannot catch it and the caller gets a 200 whose body
     dies mid-flight. /api/public/images DOES serve webp, so this was reachable
     for any tenant with a .webp logo: every card on their store, broken.
     RENDERABLE_LOGO_TYPES is the only defence and is now documented as such.
     Extension-derived Content-Type is trustworthy because validateUploadBuffer
     magic-byte checks every upload at write time.

  4. THE RATE LIMITER HUNG THE ROUTE FOR 140 SECONDS. Measured on the dev
     server with no local Redis: `GET /api/public/og` returned 200 after
     140,218ms, all of it inside checkRateLimit. lib/security/rate-limit.ts
     documents failMode "open", but that branch is a `catch` and the shared
     client is built with `maxRetriesPerRequest: null`, which tells ioredis to
     QUEUE commands forever while disconnected rather than error them.
     lib/email/tracking-rate-limit.ts had already recorded this for the email
     routes; this story generalises the fix into
     lib/security/abandonable-rate-limit.ts (race the meter against a 500ms
     deadline, carry on if it does not answer) and uses it here. A scraper that
     times out renders the link with no preview — the exact outcome the card
     exists to prevent. The email module predates it and should collapse onto
     it when something else touches that file.

SSRF, CONSIDERED AND CLOSED. tenant_branding.logoUrl is TENANT-WRITABLE. A
renderer that fetched it server-side would be an SSRF with the tenant steering
(169.254.169.254 and friends). The logo is therefore read from S3 directly —
through storedPublicImagePath, which only returns a path for a key under
tenants/{id}/uploads/, then through parsePublicImageRequest, the same
s3-tenant-guard that gates /api/public/images. An absolute URL, a presigned
link or a template asset is SKIPPED rather than fetched, and the card falls back
to a monogram chip. Reading S3 directly also avoids the container HTTP-fetching
its own public hostname out through Cloudflare and back on every uncached card.

RUNTIME = NODEJS, stated in-code with the reason (an AC). The card needs the
tenant row (Prisma) and the logo bytes (AWS SDK); neither runs on edge without a
Data Proxy this deployment does not have. next/og supports both — image-response
.js picks index.node.js when NEXT_RUNTIME is not "edge" — and reads its font and
both WASM blobs off disk with readFileSync, so the render makes no network call.

PLAN GATE. brandedOgImage returns null for anything that is not seo.pro, so a
Basic tenant's head is byte-identical to what it was before this story — the
storefront degrades, it never blocks. A direct hit on the route from a Basic
